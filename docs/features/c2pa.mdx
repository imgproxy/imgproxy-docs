# C2PA ((pro))

imgproxy can attach [C2PA](https://c2pa.org/) (Coalition for Content Provenance and Authenticity) manifests — also known as Content Credentials — to processed images. A C2PA manifest is a tamper-evident record embedded in the image that describes its provenance: who created or edited it, what software was used, and, when the source image already carries a manifest, the full edit history inherited from it.

When enabled, imgproxy signs every processed image it outputs with a C2PA manifest, using [c2pa-rs](https://github.com/contentauth/c2pa-rs) under the hood.

:::info
You can find the list of formats supporting C2PA manifests in the [c2pa-rs documentation](https://opensource.contentauthenticity.org/docs/sdk-repos/c2pa-rs/docs/supported-formats).
:::

:::warning
imgproxy doesn't sign SVG images with C2PA manifests and removes any existing ones during minification. If you need C2PA signing for SVG images, please let us know.
:::

## Configuration

* [`IMGPROXY_C2PA_ENABLED`]: when `true`, imgproxy will sign processed images with a C2PA manifest. Default: `false`
* [`IMGPROXY_C2PA_SETTINGS`]: the raw [c2pa-rs SDK settings](#c2pa-settings) string, including signing credentials, trust anchors, and verification/builder options. Takes precedence over `IMGPROXY_C2PA_SETTINGS_PATH` when both are set
* [`IMGPROXY_C2PA_SETTINGS_PATH`]: the path to a file containing the c2pa-rs SDK settings, as an alternative to providing them inline via `IMGPROXY_C2PA_SETTINGS`
* [`IMGPROXY_C2PA_FORMAT`]: the format of the C2PA settings. Can be `toml` or `json`. Default: `toml`
* [`IMGPROXY_C2PA_ACTION`]: the C2PA action recorded in the manifest for processed images. Default: `c2pa.edited`
* [`IMGPROXY_C2PA_SOFTWARE_AGENT`]: the software agent name recorded in the manifest. Default: `imgproxy`
* [`IMGPROXY_C2PA_SOFTWARE_AGENT_VERSION`]: the software agent version recorded in the manifest. Default: the running imgproxy version

### C2PA Settings

C2PA settings are used to configure the signing and verification behavior of imgproxy when working with C2PA manifests. The settings should be formatted as either TOML or JSON, depending on the value of `IMGPROXY_C2PA_FORMAT`. You can provide them either inline via `IMGPROXY_C2PA_SETTINGS` or through a file specified by `IMGPROXY_C2PA_SETTINGS_PATH`.

You need to provide at least the signing credentials (`[signer.local]` or `[signer.remote]` sections) for C2PA signing to work. Other options, such as trust anchors and verification settings, are optional but can be included as needed.

You can find the full list of supported C2PA settings in the [c2pa-rs settings reference](https://opensource.contentauthenticity.org/docs/manifest/json-ref/settings-schema/) and the [test settings example](https://github.com/contentauth/c2pa-rs/blob/main/sdk/tests/fixtures/test_settings.toml).

## Provenance and creation info

Every signed image gets an action recorded using [`IMGPROXY_C2PA_ACTION`](../configuration/options.mdx#IMGPROXY_C2PA_ACTION) (`c2pa.edited` by default), with the software agent taken from [`IMGPROXY_C2PA_SOFTWARE_AGENT`](../configuration/options.mdx#IMGPROXY_C2PA_SOFTWARE_AGENT)/[`IMGPROXY_C2PA_SOFTWARE_AGENT_VERSION`](../configuration/options.mdx#IMGPROXY_C2PA_SOFTWARE_AGENT_VERSION). This always applies and can't be overridden per request.

The source image is always included as an ingredient in the manifest, ensuring that its provenance chain is preserved.

## Disabling C2PA signing

To disable C2PA signing per request, use the [c2pa](../usage/processing.mdx#c2pa) processing option:

```imgproxy_url
.../c2pa:false/...
```

If you want to disable C2PA signing by default, you can add `c2pa:false` to your [default preset](../usage/presets.mdx#default-preset).

## Reading the manifest

You can read back the C2PA manifest of a source or already-signed image using the `c2pa` info option:

```imgproxy_url
/info/.../c2pa:1/...
```

Read more about the `c2pa` info option, including the response format, in the [Info options](../usage/getting_info.mdx#c2pa) reference.
